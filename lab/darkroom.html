Darkroom is a small headless render farm for Unreal's Movie Render Queue. I built it out of real friction on this portfolio. One GPU crash killed the whole editor render queue. A Desert job got queued on the Forest map. And the open editor held about 14 GB of RAM while rendering.

Darkroom runs each job in its own off-screen Unreal process. It checks the job before it starts, retries the job if it crashes, and keeps going with the rest of the batch. I designed it and directed the build with my agent setup: the AI wrote most of the code; the scope, the checks and the debugging calls were mine. It's v1: built for my own renders and in use for this portfolio, not a public release.

What it does

Job list: each job is a sequence, a map, a render preset and the expected frame count.
Pre-flight checks: the assets exist, the sequence matches its map, there's enough disk space for the frame count, and nothing heavy (like the editor) is still open. Finished jobs get skipped.
Builds the render queue headless: one background Unreal run writes a queue file per job, the same format the editor's own remote render uses.
One process per job: each render runs off-screen in its own process, so one crash never takes down the batch.
Crash detection and retry: reads the exit code and the log (GPU crash, fatal error) and re-runs the job.
View modes on demand: lighting-only and wireframe passes are set up automatically, so no editor is needed.
Report and encode: frames, minutes and seconds per frame for each job, then an MP4 encode with ffmpeg.
Live dashboard: the current job with its latest frame, progress and ETA, the queue, the history, and GPU, VRAM, temperature and disk.
